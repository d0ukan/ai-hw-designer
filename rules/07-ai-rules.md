## 07 · AI working rules

- [ ] **AI-01** — Before design, complete the Project Intake (G0) process in section 00; before PCB design, complete the PCB Intake (G0.5) process in section 00B. Ask the user about missing or conflicting requirements; do not start a stage before its inputs are approved.
- [ ] **AI-02** — Do not make component, net, footprint, stack-up or design rule changes without user approval.
- [ ] **AI-03** — Report to the user, with justification, design choices that may increase cost.
- [ ] **AI-04** — For a completed design, report the applied rules, any exceptions and the verification results.
- [ ] **AI-05** — Mark a checklist item complete only when it is actually verified. Leave items that cannot be verified open.
- [ ] **AI-06** — Keep design and verification scope proportional to project risk. Mark irrelevant items N/A with justification; do not produce documents, alternative designs and analyses the user did not ask for.
- [ ] **AI-07** — On stage and revision changes, create a short checkpoint using the existing Git/EDA records (commit only after the user's yes, AI-11). Preserve user changes; resume unfinished work from the last verified state.
- [ ] **AI-08** — The EDA integration method is independent. First verify existing, authorized MCP/CLI/API tools with a low-risk read/connection check. Do not use a tool function that does not exist as if it did; propose native automation or a user-assisted alternative if possible. Installing plugins, expanding permissions or sending external data requires separate user approval.
- [ ] **AI-09** — **Stop conditions — human engineer approval mandatory:** If there is mains voltage or voltage above SELV (above ≈ 60 V DC / 30 V AC rms), an isolation/safety barrier, a multi-cell lithium battery or a high-energy power stage, a patient-connected medical device, Aviation DAL A/B, or a function that affects human life, the AI cannot pass the approval gate alone. Tell the user this clearly, write it in `Project-README.md`, and request a review by a competent human engineer in the G0, G0.5 and G1 evidence.
- [ ] **AI-10** — **Keep the project in this conversation.** Do not ask the user to open a new session, chat or window to continue. Switch roles inside this conversation: use the client's in-session subagents for the Designer and the Reviewer when available; otherwise the main session does the Designer work itself and states the role it is in. For an independent review use an in-session subagent with a clean context. If the client has none, ask the user how to review (a second AI chat of their choice, a human, or a review in this chat recorded as not independent, which never counts as the second review at depth High); never require a new session. If tools such as MCP load only when the client starts, set them up at project start (INT-54) and ask the user to restart the client and resume this same conversation (e.g. `claude --continue`), not to start a new one. Open a separate session only if the user asks for it.
- [ ] **AI-11** — **No commit or push without the user's OK.** Git is optional; the project also works in a plain local folder without git (records then store design file hashes). Never run `git commit`, `git push`, `git init` or change branches on your own. When a record needs a committed design (`projectctl` says "commit the reviewed design first"), show the files and a commit message and ask the user; commit only after a yes. Push only when the user asks for it.
